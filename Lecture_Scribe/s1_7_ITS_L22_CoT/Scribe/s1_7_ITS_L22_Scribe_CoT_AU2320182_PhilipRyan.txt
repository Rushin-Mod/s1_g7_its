\section{Tail of a Random Variable}

\subsection{Definition}

The tail of a random variable is defined as:
\[
P(X > x)
\]
This represents the probability that the random variable takes a value greater than a given threshold.

\subsection{Motivation for Studying Tails}

From the slides (pages 5--7), the importance of tails is motivated through real-world scenarios:

Jobs delayed more than 24 hours

Packets dropped due to full buffer

These correspond to rare but extreme events, captured by tail probabilities.

\subsection{Key Idea}

Mean captures average behavior (easy to compute)

Tail captures rare extreme events (hard to compute)

\subsection{Why Are Tails Hard to Compute?}

Requires summing many small probabilities

Leads to complicated, long summations

This difficulty motivates the need for tail bounds instead of exact computation.

\section{Tail Examples}

\subsection{Example 1: Load Distribution Across Servers}

\subsubsection{Problem Statement}

Suppose jobs are distributed among servers at random.

What is:
\[
P(\text{a particular server gets } \geq k \text{ jobs})?
\]

\subsubsection{Reasoning from Slides}

Jobs are assigned randomly

Most servers receive few jobs

Occasionally, one server gets many jobs

This event represents a tail event (rare overload).

\subsubsection{Mathematical Formulation}

This is a tail probability of a Binomial distribution.

\subsection{Example 2: Poisson Arrivals}

\subsubsection{Problem Statement}

Jobs arrive according to a Poisson process with rate $\lambda$ jobs/hour.

What is:
\[
P(\text{at least } k \text{ jobs arrive in the first hour})?
\]

\subsubsection{Reasoning from Slides}

Jobs arrive randomly over time

Most hours have moderate arrivals

Sometimes, there is a burst of arrivals

This represents a tail event (sudden spike in load).

\subsubsection{Mathematical Formulation}

Again, this is a tail probability involving an infinite sum.

\section{Why Tail Bounds?}

\subsection{Problem with Exact Computation}

From page 14:

Binomial tail:
\[
X \sim \text{Binomial}(n, p)
\]
\[
P(X \geq k) = \sum_{i=k}^{n} \binom{n}{i} p^i (1 - p)^{n-i}
\]

Poisson tail:
\[
X \sim \text{Poisson}(\lambda)
\]
\[
P(X \geq k) = \sum_{i=k}^{\infty} e^{-\lambda} \frac{\lambda^i}{i!}
\]

These are:

Complicated

Long summations

Difficult to compute exactly

\subsection{Key Idea (Page 15)}

Instead of computing exact values:

Find an upper bound

Easier to compute

Still provides a guarantee

\subsection{Conclusion}

Core principle:
\[
\text{Exact: } P(X \geq k) = ?
\]
\[
\text{Bound: } P(X \geq k) \leq \text{something simple}
\]

Approximate safely instead of computing exactly.

\section{Running Example (Key Idea)}

We analyze all bounds using a common example.

\subsection{Setup}

Flip a fair coin $n$ times

Let:
\[
X = \text{number of heads}
\]

\subsection{Distribution}

\[
X \sim \text{Binomial}(n, \tfrac{1}{2})
\]

\subsection{Mean}

\[
E[X] = \frac{n}{2}
\]

\subsection{Tail Question}

\[
P\left(X \geq \frac{3n}{4}\right)
\]

This represents getting unusually many heads, i.e., a tail region.

\section{Markov’s Inequality}

\subsection{Key Idea (Page 18)}

Uses only the mean

Large values are rare

Example intuition:

If average is 10, very few values can be 100+

\subsection{Statement of Markov’s Inequality}

\[
P(X \geq a) \leq \frac{E[X]}{a}
\]

\subsection{Proof (Step-by-Step from Slides)}

Start with expectation:
\[
E[X] = \sum_{x=0}^{\infty} x \, p_X(x)
\]

Step 1: Restrict to large values
\[
E[X] \geq \sum_{x=a}^{\infty} x \, p_X(x)
\]

Step 2: Replace by $a$ (since $x \geq a$)
\[
\geq \sum_{x=a}^{\infty} a \, p_X(x)
\]

Step 3: Factor out $a$
\[
= a \sum_{x=a}^{\infty} p_X(x)
\]

Step 4: Recognize probability
\[
= a \cdot P(X \geq a)
\]

Final inequality:
\[
E[X] \geq a \cdot P(X \geq a)
\]
\[
\Rightarrow P(X \geq a) \leq \frac{E[X]}{a}
\]

\section{Markov’s Inequality on Running Example}

Given:
\[
X \sim \text{Binomial}(n, \tfrac{1}{2}), \quad E[X] = \frac{n}{2}
\]

Apply Markov’s Inequality:
\[
P\left(X \geq \frac{3n}{4}\right) \leq \frac{E[X]}{3n/4}
\]

Substitute mean:
\[
= \frac{n/2}{3n/4}
\]

\[
= \frac{2}{3}
\]

\subsection{Conclusion}

\[
P\left(X \geq \frac{3n}{4}\right) \leq \frac{2}{3}
\]

\subsection{Observation (from Slide)}

This is a terrible bound

Reason: it does not depend on $n$

\section{Real-Life Interpretation}

\subsection{Example: Income Distribution}

Average income = 10,000

Using Markov’s inequality:

Very high incomes must be rare, since the average is limited

This demonstrates how mean alone can bound extreme outcomes.

\section{Final Summary}

1. Tail probability measures extreme events:
\[
P(X > x)
\]

2. Exact computation is difficult due to long summations

3. Tail bounds provide simpler, safe approximations

4. Markov’s inequality:

Uses only the mean

Provides a simple upper bound

Often loose (weak)

5. Running example shows:

Tail events = rare

Bounds may lack tightness
